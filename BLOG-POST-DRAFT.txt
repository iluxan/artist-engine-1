  Building an Event Discovery Agent with Claude Code: A Day of Infrastructure Wins and Data Reality Checks

  Executive Summary

  What worked: AI-assisted coding built a complete review queue system with verification pipeline, regression testing, and polished
  UI in hours. Only 1 bug.

  What didn't work: The actual core purpose - finding real events. 100% hallucinations despite sophisticated verification.

  The pivot: Shifted from web scraping to search API discovery with rapid CLI prototyping.

  ---
  I. The Starting Point: Too Many Fake Events

  The Problem

  - Previous implementation extracted "events" like countdown timers
  - Example: "All Hallow's Read" from Neil Gaiman's homepage with date 2025-01-19 (actually a JavaScript widget, not an event)
  - No verification system
  - Events just accumulating in database

  The User's Goal

  "Archive all the current plans, make a simple plan... find events with full verification, 7-day cache, manual review queue"

  Core requirement: Stop accumulating garbage data, find REAL events

  ---
  II. Phase 1: Building the Infrastructure (What AI Does Well)

  What We Built in ~4 Hours

  Database Layer ✅
  - New unverified_events table for review queue
  - Added expires_at, approved_at, verification_status to events table
  - Functions: createUnverifiedEvent(), approveEvent(), deleteExpiredEvents()

  4-Step Verification Pipeline ✅
  1. HTTP Check - URL returns 200?
  2. AI Content Validation - GPT-4 confirms page matches event?
  3. Date Sanity - Future date, not countdown, within 2 years?
  4. Registration URL - Has ticket/RSVP link?

  API Endpoints ✅
  - POST /api/people/:id/extract-events - Extract from all sources
  - GET /api/events/unverified - Review queue
  - POST /api/events/unverified/:id/approve - Move to approved (7-day expiry)
  - DELETE /api/events/unverified/:id - Reject

  Frontend UI ✅
  - "Extract Events" buttons on person pages
  - "Review Events" page with verification badges
  - Approve/reject buttons
  - Real-time progress tracking
  - Badge showing queue count

  Regression Testing ✅
  - POST /api/test/extract-regression/:id endpoint
  - Test results page with quality score
  - Verification breakdown (HTTP ✓2/✗0, Content ✓2/✗0, etc.)

  The One Bug: Route Ordering 🐛

  Symptom: "Failed to load events" on Review Events page

  Cause: Express route /api/events/:id matched before /api/events/unverified
  - Request to /api/events/unverified hit :id handler
  - Tried parseInt("unverified") → NaN → database error

  Fix: Moved specific routes before parameterized routes
  // ✅ Correct order
  app.get('/api/events/unverified', ...) // Specific first
  app.get('/api/events/:id', ...)         // Generic last

  Time to diagnose and fix: ~5 minutes

  VI. Key Insights: AI as a Coding Partner

  What This Session Revealed

  AI coding assistants are EXCELLENT at:
  - 🚀 Rapid implementation of well-defined requirements
  - 🏗️ Building infrastructure (databases, APIs, UI)
  - 🐛 Debugging technical issues (route ordering, etc.)
  - 📝 Documentation and planning
  - 🔄 Pivoting quickly when direction changes

  AI coding assistants are WEAK at:
  - 🎯 Validating if an approach will actually work
  - 🔍 Recognizing when core assumptions are flawed
  - 💡 Proactively suggesting "wait, this won't find real data"
  - 🧪 Prototyping/testing before building full systems

  The Pattern:
  1. User: "Build X"
  2. AI: builds beautiful, complete X in hours
  3. Reality: X doesn't solve the actual problem
  4. User: "This is dumb, let's try Y instead"
  5. AI: immediately pivots, builds comprehensive Y plan

  What We Should Have Done Differently

  Better order:
  1. ❌ Build complete review queue system
  2. ✅ First: Run test-brave-search.js "Neil Gaiman" → see if we get ANY real events
  3. ✅ Then: Build infrastructure IF prototype works

  The lesson: Validate data sources BEFORE building pipelines

  Human: Strategic direction + reality checks
  AI: Rapid implementation + comprehensive planning
  Together: Fast iteration with course correction
